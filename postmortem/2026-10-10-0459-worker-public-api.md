## Findings

### 1. Parallel merges will conflict on the committed OpenAPI spec

- Category: Automated checks
- Severity: medium
- Evidence: After the merge, `docs/api/openapi.json` had to be regenerated. Every ticket that adds an endpoint will now fail `test_the_committed_openapi_spec_matches_the_app` until someone runs the export script.
- Suggested change: Add `uv run python -m scripts.export_openapi` to the backend `lint:fix` script, or to a pre-commit step that stages the result, so regeneration happens automatically.
- Target: apps/backend/package.json, .husky/pre-commit

### 2. Two Alembic heads were found only after a manual merge

- Category: Automated checks
- Severity: medium
- Evidence: Both #2 and #18 branched from d4e5f6a7b8c9. `alembic heads` showed two heads, and nothing in the unit tier flagged it.
- Suggested change: Add a unit test that loads the alembic ScriptDirectory and asserts `len(get_heads()) == 1`.
- Target: apps/backend/tests/unit/infrastructure/database/

### 3. `uv run pytest` failed in a fresh worktree

- Category: Navigation
- Severity: low
- Evidence: In a fresh worktree, `uv run pytest` failed with "Failed to spawn: pytest" until I ran `uv sync --extra dev`. The dev tools sit in optional-dependencies, not a dependency group.
- Suggested change: Add a one-line note to the notes or README saying `uv sync --extra dev` comes first in a new worktree, or move the dev tools to `[dependency-groups]`.
- Target: apps/backend/README.md

### 4. Alembic autogenerate always emits a spurious unique constraint on roles.id and user.id

- Category: Automated checks
- Severity: low
- Evidence: Every autogenerated migration includes `create_unique_constraint(None, 'roles'/'user', ['id'])`, which has to be deleted by hand, and `alembic check` always fails.
- Suggested change: Drop `unique=True` from the primary-key columns in the models, or filter these ops out in `env.py`'s `include_object`, so that `alembic check` can run in CI.
- Target: apps/backend/src/modules/user/models.py, migrations/env.py
