## Findings

### 1. Ticket #4 broke the e2e setup and its own branch never ran e2e

- Category: Automated checks
- Severity: high
- Evidence: `accounts.setup.ts` still posted `{name, email, password}` to `POST /users/` and used `E2eMember!1`. Every chromium test was skipped. Nothing caught it before the merge.
- Suggested change: Make running Playwright on a throwaway DB part of each ticket's definition of done, or run e2e in CI on PRs into the integration branch.
- Target: `.github/workflows/` CI, docs/agents ticket checklist

### 2. Tests that mutate the shared `app` leak into later tests

- Category: Coding standards
- Severity: medium
- Evidence: `test_step_up_requires_a_fresh_code` added a route and removed it by path, but `include_router` wraps routes, so it stayed and polluted the cached OpenAPI schema. The failure only showed under xdist ordering.
- Suggested change: Add a `temporary_route` fixture that snapshots `app.router.routes` and resets `app.openapi_schema`, and tell the reviewer to reject ad-hoc `app.include_router` in tests.
- Target: `apps/backend/tests/conftest.py`, CONSTITUTION reviewer rules

### 3. Parallel tickets all branch migrations off the same head

- Category: Automated checks
- Severity: low
- Evidence: Three of four branches needed `down_revision` re-pointed by hand during the merge.
- Suggested change: Add a CI check that `alembic heads` returns exactly one head, so the problem is caught on the integration branch.
- Target: CI workflow / `apps/backend/tests/unit`
