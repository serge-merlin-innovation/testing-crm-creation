## Findings

### 1. Autogenerate emits spurious unique constraints on roles.id and user.id

- Category: Automated checks
- Severity: medium
- Evidence: Every `alembic revision --autogenerate` and `alembic check` reports `add_constraint UniqueConstraint(id)` on `roles` and `user`. These lines had to be removed from the migration by hand.
- Suggested change: Drop `unique=True` on the primary-key columns in the User/Role models (it duplicates the PK), or add an `include_object` filter in migrations/env.py. Then add `alembic check` to CI.
- Target: apps/backend/src/modules/user/models.py, role/models.py, migrations/env.py

### 2. Module wiring rules found only by running the full suite

- Category: Navigation
- Severity: low
- Evidence: Missing `crud.py`, an unindexed FK and missing EXCEPTION_MAPPING entries were each caught by unit tests after the feature was written.
- Suggested change: Add a short "new module checklist" (crud.py, index every FK, map every DomainError) to the backend README or the module template docs.
- Target: apps/backend/README.md

### 3. `uv sync` silently removes dev tools

- Category: Tool economy
- Severity: low
- Evidence: After the merge, `uv sync` uninstalled ruff and the lint step failed. `uv sync --extra dev` fixed it.
- Suggested change: Move the dev tools to `[dependency-groups] dev` so that plain `uv sync` keeps them.
- Target: apps/backend/pyproject.toml

### 4. A global job registry leaks into an exact-list test

- Category: Automated checks
- Severity: low
- Evidence: test_rails asserted `ran == ["probe"]`. It broke as soon as a real job was registered and was relaxed to `in`.
- Suggested change: Give tests a fresh JobRunner, or document that the registry is shared.
- Target: apps/backend/tests/integration/foundation/test_rails.py
