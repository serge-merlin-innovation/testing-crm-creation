# Agent experience: recommendations from the M&A CRM run

The biggest opportunities found in `check-failures.log` (500 lines), `docs/DECISION-REPORT.md` (86 decisions) and the 37 run postmortems in `postmortem/` for the run of 2026-10-10 (PR #22). Each table is ordered by impact, largest first.

## Time and tokens

| Recommendation | Where | Why |
|---|---|---|
| Build Settings in tests with one `make_settings()` factory around a real `Settings(_env_file=None, **overrides)`, and drop `Mock(spec=Settings)`. | `apps/backend/tests/unit/infrastructure/security/test_production_validator.py`, a shared fixture in `apps/backend/tests/conftest.py` | The biggest single waste in the log: 66 failures. Each new setting broke 13 of the file's 20 tests at once. |
| Add `pnpm check:quick`, all unit guard tests on both sides in under 30 s. Run it in pre-commit, and name it in the worker steps after every slice. | `package.json`, `.husky/pre-commit`, `.jcode/skills/implement/SKILL.md` | Guard tests (i18n, `.env.example`, OpenAPI sync, module wiring, typography scans) surfaced only in full runs: 73 log lines and 7 postmortems. |
| Add one `pnpm test:e2e:fresh` script: a throwaway Postgres on a free port, then migrate, seed, wipe `.auth` and run. Map the compose port as `${POSTGRES_PORT:-5432}:5432`, make Playwright refuse ports 5432 and the `.env` port, and point the pre-push hook at the script. | `scripts/e2e-fresh.sh` (new), `package.json`, `apps/backend/docker-compose.yml`, `apps/frontend/playwright.config.ts`, `.husky/pre-push` | Every worker rebuilt this by hand: 11 postmortems, 25 log lines, and decisions 1, 2 and 10 (the `--no-verify` push and the deleted Docker volume). |
| Run pytest with `-n auto` by default. Keep `perf` and `slow` tests out of the default run, and leave performance budgets to the CI k6 job. Document running long suites detached with a log file. | `apps/backend/pyproject.toml`, `apps/backend/package.json`, `docs/agents/running-checks.md` (new) | Integration runs took 15 to 55 minutes under load and blew the 10-minute tool cap (6 postmortems). A wall-clock perf test flaked 24 times. |
| Add Alembic hygiene: a unit test for a single head and unique revision ids, no `unique=True` on primary keys, a modern `script.py.mako`, a ruff `post_write_hook`, and `alembic check` in CI. | `apps/backend/tests/unit/`, `apps/backend/src/modules/*/models.py`, `apps/backend/migrations/script.py.mako`, `apps/backend/alembic.ini`, `.github/workflows/ci.yml` | Duplicate ids and two heads came up in 10 postmortems, and spurious autogenerate diffs in 9. Each one cost a merge or fix cycle. |
| Turn the frontend source-scan rules into ESLint rules: typography, `toLocale*`, raw dates, `Date.now()` in e2e, `exact: true` on short role names. | `apps/frontend/eslint.config.mjs` | Today agents learn these rules by failing a vitest (34 log lines). | Test the navigation per permission ("admin sees /users"), not as a whole route list. Add "mock of a config object" and "whole-list assertion" as anti-patterns. | `apps/frontend/tests/unit/lib/app-navigation.test.ts`, `.jcode/skills/tdd/SKILL.md` | Every new page broke the exact-list assertion (18 log lines). |

## Controllability

| Recommendation | Where | Why |
|---|---|---|
| Add a rule: an agent never narrows an acceptance criterion. An ambiguous criterion takes the reading that does more. A criterion that cannot be met stops the ticket and goes to the user. | `docs/agents/CONSTITUTION.md` | 12 decisions narrowed a criterion and were reverted after review 2. The decision report looked like disclosure, so nobody pushed back. |
| Add an ambiguity sweep before the spec is confirmed. Every capability gets a role x action table, every duration and threshold a number with a unit, every enumeration its full list, every notification a recipient and trigger, every calculation a worked example, and every external service a vendor or "port plus fake". Also add "Definitions" and "Vendors and hosting" sections. | `.jcode/skills/to-spec/SKILL.md` | About 48 of the 86 run-time decisions answered questions the spec should have asked. This is the cheapest way to move them to a human, up front. |
| Add pre-flight questions: before writing code, each frontier ticket returns only its open questions, and the coordinator batches them into one message to the user. Workers may log only `interpretation` and `default-applied` decisions. Anything else ends the ticket as `blocked: needs user`. | `.jcode/skills/implement/SKILL.md` | This moves the remaining run-time interpretations to the human, for one round trip per frontier. |
| Settle the 17 engineering conventions once as ADRs: email and other external ports, test hooks, the job runner, rate limiting, the i18n catalogue, audit on every mutation, CSV-safe exports, secrets at rest, module wiring. Create `CONTEXT.md` for domain definitions and the confidentiality principle. | `docs/adr/` (new), `CONTEXT.md` (new, `AGENTS.md` already points to both) | 17 decisions were conventions the boilerplate should have decided, and 7 more were confidentiality cases of one unwritten principle. |
| Add rules: hooks are never skipped (`--no-verify` is a human act), and state the agent did not create (databases, Docker volumes, processes, stashes) is never deleted or reset. Every external service sits behind a port with an in-memory fake until a vendor is chosen. | `docs/agents/CONSTITUTION.md` | This turns 5 machine-state decisions and 3 vendor decisions into non-decisions. |
| Decide the domain-error message policy and write it as an ADR. Either route handlers raise user-facing 4xx text, or `DomainError` subclasses carry a `user_facing` marker. | `docs/adr/` (new), `apps/backend/src/modules/common/utils/error_handler.py` | `EXCEPTION_MAPPING` hides domain messages as a generic 500 by design, and agents did not know it (23 log lines, 4 postmortems). |
| Replace the decision report with one file per spec, with ticket-scoped ids (`T10-3`), fixed columns (criterion, kind, decision, why, reverse by, status), and a unit test that checks ids and criterion references. | `docs/decisions/<spec>.md` (new), a test under `apps/backend/tests/unit/` | Ids collided across parallel branches (5 postmortems), and "superseded" notes were buried in prose cells. |

## Processing

| Recommendation | Where | Why |
|---|---|---|
| Make a ticket a full vertical slice (API and screen) unless the user says otherwise, list the criteria ids it owns, and run a shared-contract ticket (registries, helpers, i18n plumbing) first. | `.jcode/skills/to-tickets/SKILL.md` | Missing UI and deferred admin screens were logged as decisions (rows 6 and 8). Parallel branches changed shared helper signatures, and that drift caused 28 log lines. |
| Make slices register themselves (routers, jobs, deal tabs), discovered by walking `src/modules`. | `apps/backend/src/infrastructure/app_factory.py`, `apps/backend/src/interfaces/api/v1/__init__.py` | Every ticket edited the same shared lists, which caused merge conflicts on each merge (2 postmortems, every merger). |
| Have the coordinator poll worker status every 15 minutes, cap concurrent full-suite runs, spawn the code reviewers itself (one per axis, with the spec axis split by epic above about 100 criteria), and have reviewers write findings incrementally. | `.jcode/skills/implement/SKILL.md`, `.jcode/skills/code-review/SKILL.md` | The coordinator sat idle for hours on wake-ups that never came. A reviewer died on a rate limit after 28 minutes without writing anything. |
| Move run knowledge into the repo: the new-module checklist and backend gotchas, e2e conventions, which check tier to run when, and the merger runbook. | `docs/agents/backend.md` (new), `docs/agents/e2e.md` (new), `docs/agents/running-checks.md` (new), `docs/agents/merging.md` (new) | These lived in `~/.jcode-notes/ma-crm/notes.md` (291 lines), outside the repo, so the next fork starts from zero. |
| Edit source files with the edit tools only, and add a hook that warns on `python3 - <<` or `sed -i` against `src/`. | `docs/agents/CONSTITUTION.md`, the harness hooks | Bulk script edits silently dropped code (6 postmortems). |
| Give the failure logger a `phase` column (`red` for new or modified test files, `regression` otherwise), daily rotation instead of the 500-line cap, and a worktree column. Have `retro-auto` report tests that failed 3 or more times. | `scripts/check-failures/log.mjs`, `.jcode/skills/retro-auto/SKILL.md` | The log cannot tell planned TDD reds from waste, and it lost the run's first six hours. A repeat failure is the cheapest signal that an agent is stuck. |
